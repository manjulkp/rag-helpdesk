Helpdesk RAG

A help desk that answers engineers' questions about two project repositories with cited answers: follow-ups in context, a clarifying question when it's ambiguous, a refusal when it's off-topic, a hand-off to a person when the docs don't say, and per-user access control. What was built, what each step measured, and what was kept.

Scale, read this first. Everything here was measured on a small corpus: 2 repositories, 25 documents, 97 chunks, with hand-written golden sets (15 questions, 12 conversations, 30 policy cases, 7 conflict cases). Most differences between variants are one or two questions, and no bootstrap CI below is clear of zero. Read the numbers as direction, not size.

The problem

Engineers ask "where is X", "how does Y work" and "which test covers Z" about two projects: a multi-agent commodities research desk and a trader / risk-manager trade desk sign-off app. Answers have to come from the projects' own Markdown docs and pytest files, cite the exact lines, say when the docs don't cover something, and never show one team another team's repo.

Five decisions

  1. LLM context for retrieval, the header for the gate. The Haiku-written sentence is the only variant that found every answer chunk in the top 20, and it fixes the one failure a header can't: vocabulary the chunk lacks (it links "gold" to the ticker GC=F: rank 1-2 vs 14-19). The free header wins where the heading is the best keyword and separates real questions from off-topic ones best at the gate. Both are cheap: $0.036 for the whole index.
  2. Condense follow-ups; don't concatenate history. Both find the answer, but joined history ranks it lower on 8 of 12 turns and drags the old topic into a quarter of the results after a topic switch. Condensing costs one cached Haiku call per follow-up.
  3. The policy routes; the evidence decides whether something is answerable. The first policy judged "is it answerable?" from five hit titles before anything was read. Now it only judges scope (and asks which project when the hits are split), and an in-scope question escalates after the gate finds nothing or the answer step says "not found". The answer step reads the text and refused every off-topic question in every run.
  4. No Claude rerank by default. On this corpus plain Haiku answered 10/10 and refused 5/5 from plain retrieval; the gated rerank added calls and latency and slightly lower citation recall. It stays an option for a bigger corpus, where a top 8 is harder to get right.
  5. Two access layers, and forbidden looks like missing. A metadata filter on search is one bug away from a leak, so every other path a chunk can take is filtered again (tested with poisoned sticky sources). A user asking about a repo they can't see gets the same "I couldn't find this" as for anything undocumented, because confirming that a document exists is itself a leak.

Anthropic reports $1.02 per million document tokens for contextual retrieval. This corpus costs about 2.7x that: its documents are tiny (3.9 chunks each), so each document's first cache write is a large share, and the generated contexts (22,870 output tokens) outweigh the corpus itself.

Failure modes and limits

  • Small, self-written golden sets. 15 questions, 12 conversations, 30 policy cases; the same author (with AI assistance) wrote the questions and the system, so they share blind spots. One question moves a rate by up to 0.1.
  • No git history here. Every source's date shows "unknown" and hand-offs suggest no contact. Git authorship isn't ownership anyway; a real deployment needs an owners map.
  • No genuine conflicts in the corpus. The conflict handling is tested on synthetic copies with one number changed.
  • Known misses. "How do I run the tests for the research desk?" doesn't retrieve the README's Run section (test-file headers crowd it out), so it escalates. "Translate 'risk manager'" names a project alias, skips the scope check, and escalates instead of being refused.
  • Red-team gap. Two attack prompts are tested; prompt injection inside retrieved documents is not.
  • Windows encoding. A cp1252 default silently dropped whole prompts that contained one non-cp1252 character; fixed (UTF-8 everywhere), worth checking in any new subprocess call.

What I'd do next

  1. Grow the golden sets with questions written by people who didn't build it, including identifier-style and split-section questions, where LLM context should matter most.
  2. Fix the "run the tests" retrieval miss (down-weight bare test-module headers) and drop the "names a project, so in scope" shortcut.
  3. Real clones with git history, an owners map for hand-offs, and permissions from the directory, re-checked per request; consider one collection per team.
  4. Red-team prompt injection in retrieved text, and apply the access rules to caches, sessions and tickets.
  5. Measure on real traffic before tuning further: clarifying-question rate, escalations per day, refusals users disagree with.
